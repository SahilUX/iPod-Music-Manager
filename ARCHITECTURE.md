# Architecture

Reference for developers working in this repo. Reflects the codebase as of **v2.1 (build 21)**. The older `DESIGN.md` / `PRD.md` / `BRD.md` are the original v1.0 product specs — useful for intent, but this file is the source of truth for current architecture and behavior.

## What this app is

A native macOS (SwiftUI, macOS 14+) app that converts a self-hosted [Navidrome](https://www.navidrome.org/) FLAC library into Apple Music, and keeps Navidrome playlists mirrored into Apple Music (and onward to a classic iPod). The end target is an **iPod mini (1st gen, 4 GB)** synced through Apple Music / Finder.

## Build, run, install

The Xcode project is **generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)** from `project.yml`. Source files are globbed from `iPodMusicManager/`, so **new files require regenerating the project**:

```bash
xcodegen generate        # after adding/removing source files
```

Build (Release) without code signing, and install over the running app:

```bash
xcodebuild -project "iPodMusicManager.xcodeproj" -scheme iPodMusicManager \
  -configuration Release build CODE_SIGNING_ALLOWED=NO 2>&1 | grep -E "error:|BUILD"

APP=$(find ~/Library/Developer/Xcode/DerivedData -path "*Build/Products/Release/*.app" -name "iPod Music Manager.app" | head -1)
osascript -e 'quit app "iPod Music Manager"'; sleep 2
rm -rf "/Applications/iPod Music Manager.app"
cp -R "$APP" "/Applications/iPod Music Manager.app"
open "/Applications/iPod Music Manager.app"
```

**Version** lives in `project.yml` under the target's `info.properties` (`CFBundleShortVersionString` / `CFBundleVersion`). Bump it there, then `xcodegen generate` regenerates `iPodMusicManager/Info.plist`. Commit `project.yml`, `Info.plist`, and `project.pbxproj` together.

**External tools:** `ffmpeg` (Homebrew, needs `libmp3lame` + `alac` — both in the default formula) and Apple's `/usr/bin/afconvert`. Apple Music is controlled via `/usr/bin/osascript`.

## Architecture

SwiftUI app wired in `App/iPodMusicManagerApp.swift`, which constructs the shared objects and injects them as `@EnvironmentObject`s:

- `NavidromeClient` (Services) — Subsonic REST API: browse, download FLAC, cover-art URLs. Credentials in `CredentialStore` (UserDefaults-backed; aliased `KeychainHelper`).
- `QueueViewModel` (ViewModels) — the import queue. Downloads → converts → imports → records.
- `LibraryViewModel` (ViewModels) — library browsing state.
- `PlaylistSyncService` (Services) — linked-playlist sync with timers.
- `ImportRecordStore` (Models) — provenance of imported tracks (UserDefaults JSON).
- `LibraryReprocessor` (Services) — re-applies format/quality/art settings to existing tracks.
- `ConversionPipeline` (Services) — ffmpeg/afconvert conversion.
- `AppleMusicService` (Services) — all Apple Music control via AppleScript.
- `iPodService` (Services) — detects/ejects/syncs the iPod via `NSWorkspace` + Music.

### Import data flow (QueueViewModel.processJob)

1. Build a tolerant **library index** once per queue run (`TrackMatch.key` → track database ID).
2. Per job: if the track's key is already in the index → **duplicate**: don't re-import, just add it to the target playlist by database ID; mark `.alreadyInLibrary`.
3. Otherwise: download FLAC (or use local file) → `ConversionPipeline.convert` → `AppleMusicService.importTrack` (returns the new track's **database ID**, or nil if Apple Music silently rejected it) → add to playlist by ID → write an `ImportRecord`.

## Conventions & gotchas (read before changing sync/import code)

- **Apple Music silently rejects FLAC.** `add POSIX file` on a FLAC returns success but adds nothing. Never trust the `add` call — `importTrack` returns the new track's **database ID** (nil = rejected). FLAC is offered as an output format but warned against in Settings; re-processing into FLAC is blocked.
- **Metadata mismatch is the norm.** Navidrome's reported tags and the file's embedded tags disagree constantly, especially multi-artist tracks ("A, B, C" vs "A") and "feat." titles. So:
  - **Fuzzy identity** uses `TrackMatch.key` (in `Models/ImportRecord.swift`) = normalized title (strips `(feat. …)`, punctuation, folds case/accents/smart-quotes) + **primary artist** (first credited name). `ImportRecord.key` delegates to it. Used for dedup, scanning, sync reconciliation.
  - **Exact operations** (add-to-playlist, remove-from-playlist, delete, replace) use Apple Music **`database ID`**, never title/artist `whose` clauses. This is deliberate — title/artist matching caused false "rejected" errors and missed removals.
- **Replace is import-verify-then-delete.** `LibraryReprocessor.reconvert` imports the new file and confirms a new track landed *before* deleting the old one (by database ID). A rejected/unsupported format aborts without deleting. This exists because an earlier delete-before-verify + FLAC combo **wiped the user's library** — do not reorder it.
- **No `activate` in `importTrack`.** Adding a track must not steal focus. (`iPodService` sync keeps `activate` — it's a deliberate user action.)
- **Playlist sync reconciles membership** (`PlaylistSyncService.syncNow`): every current Navidrome-playlist track that's in the library is ensured present in the Apple Music playlist (add by ID, dedup-safe); tracks not in the library are enqueued. This self-heals playlists left empty by older bugs and re-downloads tracks missing from the library (no separate self-heal step).
- **Library-only links** (`PlaylistLink.libraryOnly`): import into the Apple Music library with **no** playlist created/maintained (reach the iPod via whole-library sync). Removals just forget the track; they never touch the library.
- **AppleScript reads use an "OK" marker.** `allLibraryTracks` / `playlistTrackIdentities` prefix output with `OK` so a read *error* (nil) is distinguishable from a genuinely *empty* result. Never treat nil as empty when it can trigger destructive/sync decisions.

### Conversion (ConversionPipeline)

- Output formats (`OutputFormat`): `.aac` (afconvert, Apple's encoder), `.alac` (ffmpeg, single-pass), `.mp3` (libmp3lame), `.flac` (passthrough copy).
- Quality tiers (`QualityTier`) apply to lossy only: Maximum 320 / High 256 / Medium 192 / Low 128 kbps.
- Album-art embedding is a toggle; optionally carries the source's attached picture.
- **ALAC keeps source resolution** (no resample) — hi-res 24/96 stays hi-res, which the iPod mini can't play (max 16-bit/48 kHz ALAC). The AAC path resamples to 44.1 kHz. Intended: keep lossless in Apple Music, let Finder's "convert to 256 kbps AAC on sync" handle the iPod.

### Settings (`@AppStorage` keys)

`outputFormat`, `outputQuality`, `embedAlbumArt`, `preferredAppIcon`. Read in `QueueViewModel.processJob` and `LibraryReprocessor`.

## Verifying changes

Prefer **non-destructive AppleScript checks** for Apple Music behavior: match by database ID, verify by library-count delta or new-ID presence, and always clean up test tracks/playlists. When testing conversions, run the exact `ffmpeg`/`afconvert` commands the pipeline issues and `ffprobe` the output. There is no unit-test suite; verification is manual/scripted.

## Persistence

- Playlist links: `UserDefaults` key `com.sahil.ipm.playlistLinks` (JSON, `PlaylistLink` has backward-compat `init(from:)`).
- Import records: `UserDefaults` key `com.sahil.ipm.importRecords`.
- Credentials: `UserDefaults` suite `com.sahil.iPodMusicManager`.

## Known limitations

- Fuzzy matching can collide (same title + primary artist, different track) — rare; acceptable trade-off.
- Sync reconciliation reads the full library once per sync; fine at hundreds of tracks, would want a cache at thousands.
- FLAC output can't be imported to Apple Music (Apple limitation).
